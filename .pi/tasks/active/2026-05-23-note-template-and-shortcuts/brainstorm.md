# Brainstorm: note template and hidden shortcuts

## Original ask

User-provided brainstorm idea:

1. Adjust default note so first heading is `## h2` and add space before and after heading.
2. Add shortcut command `/notes add <name> ...` do not show in help list or README.md. This is the same command as `/notes new <name> ...`.
3. Add shortcut command `/notes list ...` do not show in help list or README.md. This is the same command as `/notes ls ...`.

Lifecycle action selected: Create new brainstorm.

## Goal

Make note creation defaults and a pair of undocumented convenience aliases friendlier without changing the public command list.

## Current code context

- `src/core/format.ts` owns empty note markdown. `createEmptyNoteMarkdown()` currently renders frontmatter plus a body of `# ${title}\n`.
- `src/commands/shared.ts` owns setup starter-note content. `renderSetupStarterNote()` currently uses `# Welcome to notes` and command hints based on `/notes new` and `/notes ls`.
- `src/commands/handlers/index.ts` owns subcommand routing. It currently maps `new` to `handleNew` and `ls` to `handleLs`, with no aliases for `add` or `list`.
- `src/commands/notes.ts` reports unknown subcommands with `NOTES_USAGE`, so alias registration is the direct compatibility point.
- `README.md` and `NOTES_USAGE` intentionally list public commands. The requested aliases should remain hidden from both.
- Existing tests in `tests/commands.test.ts` and `tests/parser.test.ts` cover command routing and parser behavior. Alias and default-template expectations should be added there or in nearby focused tests.

## Draft implementation shape

- Change `createEmptyNoteMarkdown()` so newly created notes use a first body heading with `## ${title}` and a blank line before/after the heading in the body.
- Decide whether the setup starter note should also use an h2 heading, because the user said "default note" and the code has both empty note creation and setup starter-note creation paths. Initial interpretation: apply the h2/spacing standard to note content generated by both `/notes new` and `/notes setup`, unless implementation planning narrows this.
- Register hidden aliases in `NOTES_HANDLERS`:
  - `add: handleNew`
  - `list: handleLs`
- Do not add `/notes add` or `/notes list` to `README.md` command lists or `NOTES_USAGE` help output.
- Preserve parser edge-flag semantics; aliases should use the same parsed args and scope handling as their canonical commands.

## Acceptance ideas

- `/notes new demo` creates markdown whose first body heading is `## demo` and has blank-line spacing around/after the heading as specified.
- `/notes add demo` behaves the same as `/notes new demo`.
- `/notes list` behaves the same as `/notes ls`.
- Help output and README command lists continue to omit `add` and `list`.
- Validation still passes: `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`.

## Notes for planning

This is a small implementation task touching command routing, generated markdown format, docs/help non-exposure guarantees, and tests. No destructive or migration behavior is expected.
