# Stories and acceptance criteria

## ST-001 — Safe note storage

As a user, I want note operations confined to regular files under regular notes directories so a repository cannot redirect them through symlinks.

Acceptance criteria:

- Reads, lists, search, create, append, write/edit/rewrite, move, rename, delete, setup, and uninstall reject relevant symlinked components or entries.
- Canonical containment is checked in the protected operation window.
- Project and global behavior are covered.
- The reproduced external-target mutation no longer occurs.
- Extension storage uses `CONFIG_DIR_NAME`; CLI defaults remain backward compatible.

## ST-002 — Coordinated and cancellable mutation

As a Pi user, I want concurrent tools and aborts to preserve note integrity and intent.

Acceptance criteria:

- Extension mutations use Pi's shared file mutation queue over complete read-modify-write windows.
- Multi-path acquisition is deterministic and does not deadlock.
- CLI/internal calls retain local serialization.
- Pre-aborted and queue-wait-aborted operations make no mutation.
- Cross-process limitations are documented, not overstated.

## ST-003 — Truthful command and tool outcomes

As an agent or automation client, I want schemas and error metadata to reflect actual outcomes.

Acceptance criteria:

- A typed domain outcome is independent of notification severity.
- Missing/blocked requested tool operations throw and become `isError` results.
- Empty list and no-match grep remain successful.
- Rename/move tool schemas have no overwrite property.
- Conflicts return exact `/notes ... --overwrite` human handoffs.
- TUI/RPC and CLI presentation/exit behavior remain coherent.

## ST-004 — Recoverable output and headless observability

As a headless or agent user, I want bounded output without losing data or receiving silent success.

Acceptance criteria:

- Large tool output is truncated at Pi limits and complete output is stored in an owner-only OS temp artifact.
- Result text/details expose artifact path and structured truncation metadata.
- Retention is bounded but permits a same-session follow-up read.
- Relevant descriptions document limits.
- Print/JSON commands emit a safe observable result, or an observable unsupported result with CLI handoff if the Pi prototype proves direct output unsafe.
- RPC/TUI output is not duplicated and model context is not polluted.

## ST-005 — Predictable package and release behavior

As a maintainer, I want installs and publication to use host core packages and intentional release controls.

Acceptance criteria:

- Coding agent and TypeBox are `"*"` peers with tested dev versions and no TypeBox runtime dependency.
- Lockfile and package-resource tests reflect this contract.
- `npm pack --dry-run` contains required extension/CLI resources without bundled core runtimes.
- CI uses `npm ci`.
- Publish workflow uses `release.published` and protected `workflow_dispatch`, checks tag/version agreement, preserves provenance/least privileges, and declares or documents the protected environment.
- No publish occurs during execution.

## ST-006 — Accurate evidence and documentation

As a user or maintainer, I want documentation and tests to describe proven behavior.

Acceptance criteria:

- README, docs, bundled skill, changelog, and docs index match implementation.
- Security docs distinguish lexical validation, canonical containment, symlink rejection, and residual trust.
- Concurrency docs distinguish Pi/in-process coordination from cross-process behavior.
- Commands docs include mode matrix and exact destructive handoffs.
- Regression tests cover all audited boundaries.
- `dist/` is regenerated by build and the complete validation gate passes.
